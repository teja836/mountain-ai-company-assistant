5. RETRIEVAL-AUGMENTED GENERATION (RAG)

RAG combines information retrieval with language generation.

The document ingestion process can include:
- Loading supported files
- Extracting text
- Cleaning unnecessary content
- Splitting text into chunks
- Generating embeddings
- Storing embeddings and metadata
- Retrieving relevant chunks for a question

When a user asks a question, the retriever searches for
relevant information. The language model then uses that
context to produce a readable response.

Document metadata may include:
- Document identifier
- Document title
- Source filename
- Page number, when available
- Access classification
- Last updated date

Documents must be filtered by access permissions before
their content is provided to the language model.

6. STRUCTURED AND UNSTRUCTURED KNOWLEDGE

Structured information includes services, prices, products,
FAQs, contact records, and project status. This information
is suitable for relational database tables.

Unstructured information includes company profiles,
long-form service descriptions, policies, guides, and
technical documentation. This information can be indexed
for semantic retrieval.

The assistant may combine database results and retrieved
document passages to answer questions that require both.

For example, a question about a service's price and features
may require a database lookup for the price and document
retrieval for the detailed features.

7. WORKFLOW AUTOMATION

Workflow automation can connect applications and reduce
repetitive manual tasks.

Example workflow:
1. An administrator uploads a new document.
2. The system validates the file.
3. Text is extracted and divided into chunks.
4. Embeddings are generated.
5. The vector index is updated.
6. The administrator receives a processing result.

n8n may be used to orchestrate this workflow, where useful.
For the initial local prototype, the document processing
pipeline may also run directly through Python and FastAPI.

9. DATABASE AND API DEVELOPMENT

APIs allow the frontend and backend to exchange information.

The sample architecture uses FastAPI to expose endpoints,
MySQL to store structured information, and a vector database
to retrieve semantically relevant document chunks.

Database design should consider:
- Primary keys and relationships
- Input validation
- Appropriate data types
- Query performance
- Authentication and authorization
- Backup and recovery requirements
- Protection of sensitive information

API errors should provide clear messages without exposing
passwords, tokens, database credentials, or internal stack
traces to ordinary users.

13. SECURITY AND PRIVACY

The public chatbot may answer questions using approved
public company information.

The administrator interface may access additional internal
documents and business records, subject to authorization.

Required safeguards include:
- Authentication for protected endpoints
- Role-based access control
- Server-side authorization checks
- Validation of uploaded files
- Document-level access filtering
- Safe handling of credentials
- Protection against unauthorized data retrieval

A language model's instructions must not be treated as a
replacement for backend authorization.

14. ADMINISTRATOR RESPONSIBILITIES

An authorized administrator may:
- Upload approved knowledge documents
- Update company service records
- Review document processing status
- Remove outdated information
- Review chatbot conversations where permitted
- Inspect common user questions
- Verify that answers cite appropriate sources

Administrative operations should be logged when
appropriate, and access should be restricted to authorized
accounts.

15. CHATBOT ANSWERING GUIDELINES

The assistant should:
- Answer directly and clearly
- Prefer current approved company information
- Use structured data for exact database facts
- Retrieve relevant passages for document questions
- Combine both sources when necessary
- Explain uncertainty when evidence is missing
- Avoid inventing prices, policies, or capabilities
- Keep private administrative information restricted
- Provide source references when available
